# TICKET-023: Redesign invitation, guest and RSVP tables to match the PRD

## Context

The current schema puts the QR on each guest and has no invitation status, token or tag-along limit; the PRD makes the invitation the unit the gate checks.

See: [Data model](../docs/prd.md#data-model) · [Invitations and RSVP](../docs/prd.md#invitations-and-rsvp) (INV-2, INV-4, INV-6) · [Current state](../docs/current-state.md).

## Scope

- ADR for the schema change.
- invitations: token (≥128-bit, unique), max_tag_alongs, status (draft, sent, rsvp_yes, rsvp_no, revoked), token_version, table_id, sent_at, side.
- guests: name, email, phone (E.164), is_primary, meal_choice, dietary_notes.
- rsvps: attending, count_attending, responded_at.
- Generated migration (no hand edits).

## Out of scope

- Check-in/menu/order/staff tables (TICKET-024).
- Seed (TICKET-026).

## Acceptance criteria

- [x] Migration generated by `pnpm db:generate` applies cleanly twice.
- [x] Constraints: token unique and non-null; max_tag_alongs between 0 and 10; one RSVP per invitation.
- [x] No `qr_token` on guests remains.
- [x] Schema unit tests cover each constraint against a real local DB.

## Test plan

- Unit: Constraint tests against the local stack.
- Gate: `pnpm verify` passes; UI tickets also record the UI checklist (docs/ui-checklist.md).
