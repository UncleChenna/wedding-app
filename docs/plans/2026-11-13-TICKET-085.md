# TICKET-085 — WhatsApp order alerts

2026-11-13. Base: origin/develop when the managed worktree was created.

Implement the configured Cloud API template sender, bounded retries for explicit provider rejections,
recorded station opt-in and a staff-board health summary. Unconfigured sending must leave queued alerts
untouched. No live recipient will be contacted during development.

The current logging sender incorrectly marks messages sent, and the transaction around network I/O
can replay an accepted message after rollback. Replace the production path with a committed claim
before network I/O: reserve due rows as failed until provider acceptance is recorded. An interrupted
or ambiguous attempt stays visibly failed and is never automatically replayed. This deliberately
prefers a visible missed alert over a duplicate; the order board remains authoritative. Keep the
legacy test/dry-run drain contract intact. No migration is required for this state transition.

Use approved template configuration (one body text parameter), reject oversized payloads rather than
truncate order instructions, and recheck opt-in before every recipient attempt. Explicit structured
transient rejections allow three retries with bounded backoff; timeouts, transport failures and
unrecognized responses are ambiguous and are not retried. API acceptance is not phone delivery.

Verify mocked HTTP, opt-out/partial delivery/repeated drain behavior, durable claims with isolated
PostgreSQL, and staff-board warning rendering/accessibility. The live staff-phone criterion remains
open until TICKET-083 provides a configured account, template and consenting recipient. Update ADR
0022 with the changed delivery guarantee and deployment/rollback steps.
