# TICKET-024 plan — 2026-11-04

Owner divine, branch TICKET-024, base develop df8a970bc88b2c7b6664f26190a6c49abd8d3e1e.

## Outcome

Store each scan attempt immutably, preserve legacy check-ins, and separate reported
physical admissions from bounded canonical admissions. This implements the storage
contract needed by TICKET-058 and TICKET-173, not scanner UI or reconciliation APIs.

## Design and verification

1. Preserve the old `check_ins` table and its rows. Add `scan_events` and
   `admission_counters`; do not rename/drop the guest-level archive.
2. Store unique client event IDs, device and server times, reported and canonical
   results/counts, staff/device references and a nullable invitation reference.
   All five PRD results must be representable. No PIN, QR token or invitation secret.
3. Keep per-invitation canonical counts within their authoritative RSVP allowance.
   Enforce this in PostgreSQL, including concurrent inserts and RSVP decreases;
   a self-declared client allowance is not authoritative.
4. Use an expand/backfill/guard sequence. Legacy rows remain byte-for-byte intact;
   copied evidence retains original identifiers/timestamps and clearly labels import.
   Unknown legacy staff/device values must not be silently replaced with invented identities.
5. Real database tests: empty and populated legacy schemas, retries, malformed counts,
   all results, unknown invitations, foreign keys, immutable update/delete/truncate,
   over-capacity and concurrent admission, and rollback on failed import.
6. Generate migrations through Drizzle, inspect SQL, obtain exact-path approval before
   committing protected output, migrate twice and compare counts, check every table's RLS.
7. Run full verification, publish detailed evidence and a PR to develop.
