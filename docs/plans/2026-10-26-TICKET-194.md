# TICKET-194 — Validate before reserving IDs

Build and parse a provisional ticket, including actor and creation-status validation, before any shared ledger mutation. Only valid requests reserve the next unique ID. Preserve allocation compare-and-swap and never recycle IDs.

Regression tests use real disposable Git remotes: invalid estimates/priorities/statuses and missing ownership leave ledger head and lastId unchanged; a following valid request receives exactly the next ID. Existing concurrent claim and allocation tests remain. Run focused tests, quick/full verification, then the PR gate. No database, CI or product UI changes.
