# Plan: Add fixed semantic status tokens for valid, used and invalid

- Task: TICKET-010
- Module(s): theming
- Date: 2026-10-22

## Goal

Give every theme green/amber/red status tokens whose meaning cannot change between themes, checked for contrast and hue, and visible on /dev/theme.

## Acceptance criteria

- [x] Every theme defines the status tokens and passes AA for each status foreground/background pair.
- [x] Hues stay within a documented range across themes (green, amber, red).
- [x] /dev/theme shows the three statuses with text labels in both themes.

## Approach

1. `lib/schema.ts`: add `warning`, `warning-foreground` and `<status>-subtle(-foreground)` for success, warning, danger.
2. `lib/contrast.ts`: add text pairs (4.5) and indicator pairs (3.0) for every status.
3. `lib/status.ts`: kinds, tokens, hue ranges (red wraps), saturation floor, `checkStatusHues`; `loadTheme` rejects violations.
4. Theme JSON values chosen to satisfy both gates; fixture updated; `pnpm themes:schema` (owner-approved).
5. `globals.css` mapping, `/dev/theme` Status section, smoke assertions, docs/theming.md.

## Tests first

`status-tokens.test.ts`: tokens exist, contrast pairs present, every theme defines them, hue maths and wrap, every theme in range, blue success and grey warning rejected. Failed before `lib/status.ts` existed.

## Risks and open questions

- Light-theme amber must be dark (honey) to reach 3:1 on white; the tinted panel carries the bright amber.
- Staff result components that consume these tokens are TICKET-019.
