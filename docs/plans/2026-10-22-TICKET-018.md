# Plan: Add form components for RSVP, ordering and admin

- Task: TICKET-018
- Module(s): shared (base UI)
- Date: 2026-10-22

## Goal

One set of accessible, token-based form controls for RSVP (TICKET-040), ordering (TICKET-050) and admin (TICKET-070).

## Acceptance criteria

- [x] Every control has an explicit label and an error state tested for `aria-invalid` and `aria-describedby`.
- [x] QuantityStepper respects min/max and is keyboard operable.
- [x] All controls are ≥44px tall at 375px.

## Approach

1. `field.tsx`: `useFieldIds`, `FieldMessages` (polite live error), `Field` render prop, shared control classes.
2. Native-element components: Textarea, Select, Checkbox, RadioGroup; client `QuantityStepper`.
3. Move `Input` onto the shared parts.
4. `/dev/theme` form-controls card; extend the 375px sweep and add a browser keyboard test.

## Tests first

`form-controls.test.tsx`: label, aria-invalid, aria-describedby and live region per control; stepper bounds, disabled buttons, keys and clamping; 44px classes. All failed before the components existed.

## Risks and open questions

- Native checkbox/radio styling follows the browser (tinted with `accent-primary`); a fully custom look can come later if the design needs it.
