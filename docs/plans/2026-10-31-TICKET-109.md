Offer installation on staff pages and alongside actual invitation pass content only when the browser provides beforeinstallprompt. Wait for visitor interaction rather than showing on first paint. 1. Test eligibility, interaction gating, dismissal expiry, unavailable storage, one-shot prompting and installed-event cleanup with stub browser events.
2. Implement a small client boundary and shared token-based controls; mount on the staff layout and conditional invitation pass section. Demonstrate on /dev/theme.
3. Exercise browser events, keyboard navigation, native prompt rejection, route navigation, reduced motion and persisted dismissal. Capture every theme at 375/768/1280.
4. Run quick and full verification; report physical installation and WhatsApp checks as unverified until tested. Preserve existing zero-CLS assertions.

## Risks

Pass functionality remains owned by TICKET-044; icons and full installability remain separate tickets. Storage can be unavailable; dismissal must still hold for the current session. Capture must survive route changes and avoid multiple native prompts when theme demos render together.
