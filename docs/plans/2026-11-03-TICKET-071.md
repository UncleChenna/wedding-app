# TICKET-071 plan

Owner unclechenna (claude); isolated branch TICKET-071 from origin/develop after TICKET-070 (#80) merged. TICKET-070 is
done in the ledger; no one else holds ordering menu work.

## Outcome

Once a table is confirmed, `/order` shows the real menu from `menu_items`, grouped as Meals, Soft drinks and Alcoholic
drinks. Sold-out items stay visible, say "Sold out" in text, and their quantity choice is disabled. Availability changes
reach an open page without a reload.

## Approach

- `lib/menu.ts`: category order and labels, guest-safe `MenuItem` shape, `groupMenu`, and a Zod schema for the
  availability payload.
- `server/menu-repository.ts`: Drizzle read of id, name, description, category, per-order cap, availability and dietary
  tags. Station and timestamps are not exposed.
- `server/menu.ts`: `loadMenu` returns `ready` or `unavailable` with no raw errors; `menuAvailabilityResponse` returns
  `{ items: [{ id, available }] }` with `private, no-store`.
- `src/app/api/menu/availability/route.ts`: per-request GET calling the module.
- `components/menu-sections.tsx` (client): renders the server-provided menu, polls availability every 3s while the
  page is visible (and immediately on becoming visible), disables and clears sold-out choices, and announces each
  change in a polite live region. Choices are local state only; the cart and submission remain TICKET-072/074.

Polling, not Supabase Realtime: Realtime on `menu_items` would need anonymous read policies, which is an RLS change
requiring an ADR. 3s polling meets the 5s criterion; the service worker already leaves `/api/` network-only.

No photos: `menu_items` has no image column and adding one needs a migration. Items render without images; a later
ticket can add the column and `next/image`.

## Verification

Unit tests for grouping, repository mapping, load failures and the availability response. Component test for sold-out
text, disabled controls, live updates clearing a choice, and the announcement. Opt-in browser test
(`RUN_MENU_BROWSER_TESTS=1`) that seeds fixtures, opens the menu, flips an item to sold out in the database and expects
the disabled state within 5s, plus screenshots and axe in every theme at 375/768/1280. Full `pnpm verify`.
