# TICKET-059 scanner implementation plan

Build ahead of TICKET-057; keep draft until its verified repair is integrated.
Root owns this worktree. Base: develop 1f619b05. No database started.

- Keep live gate authentication; never expose raw decoded QR values in logs or UI.
- Camera starts on explicit action, prefers rear camera, stops on unmount/hidden page.
- Native BarcodeDetector when supported; lazy ZXing fallback. Decode actual video pixels
  in Chromium/WebKit fake-stream tests, not stubbed decoder return values.
- Three-second suppression per code, including alternating-code cases. Torch only
  when supported; permission/unavailable/retry states with readable instructions.
- Result/admission workflow remains TICKET-060. Manual search is TICKET-063 and is
  not yet implemented; recovery must not link to a nonexistent page or claim admission.
  Resolve the recovery destination before claiming the permission criterion complete.
- Existing approved QR verification provides the credential boundary; do not mistake
  decoding or signature validity for admission. Offline snapshot/admission remains later tickets.
- Unit camera lifecycle/throttle tests; real-auth browser fake streams in both engines;
  mobile screenshot review, all-theme axe, keyboard/reduced motion and responsive checks.
  Real printed/on-screen phone scans remain explicitly unverified release requirements.

Initial throttle test fails on missing module; implementation follows that regression.
