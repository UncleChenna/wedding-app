# TICKET-219: fail-closed direct review transitions

Fix the direct `t:move in_review` path: its preflight reports verification as true
and the final ledger callback overrides actual evidence. This follow-up is separate
from merged TICKET-215 and carries only the two source/test changes prepared while
that PR was merging.

## Scope and acceptance

- Keep preflight checks cheap without mistaking them for completed verification.
- Require successful verification for the current HEAD before changing the ledger.
- Keep successful `t:pr` verification reusable within that same invocation.
- Do not accept inherited environment variables as proof of verification.
- Preserve ownership, clean-tree, pushed-head, acceptance and PR checks.

## Verification

Real-Git CLI regressions use isolated fake verifier/GitHub executables. Prove failure
leaves the ledger and ticket untouched, success invokes verification and advances
review, forged markers cannot bypass it, and HEAD changes invalidate the result.
Also verify the PR path invokes the verifier once and rejects changing HEAD.

Four direct transition scenarios failed before implementation because no verifier
ran. They passed after the fix. The expanded ticket/evidence/artifact suites passed
50 tests and quick verification passed in the original clean integration checkout;
rerun checks on this isolated branch before review.
