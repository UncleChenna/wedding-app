# Plan: Guard against horizontal overflow on phones

- Task: SETUP-001
- Module(s): theming (e2e only)
- Date: 2026-10-21

## Goal

Fail the smoke suite if any current route scrolls sideways on a 375px-wide phone.

## Acceptance criteria

- [ ] A @smoke Playwright test loads /, /invite, /order, /checkin, /kitchen, /admin and /dev/theme at 375px wide and asserts document scrollWidth <= clientWidth on each
- [ ] The test runs as part of pnpm test:e2e:smoke (mobile project)
- [ ] pnpm verify passes

## Approach

1. Create `e2e/overflow.spec.ts` with a `describe("no horizontal overflow @smoke")` block.
2. Override the viewport to 375×812 (the Pixel 7 device in the `mobile` project is 412px wide, so the override is needed to hit the 375px design width).
3. Skip the test outside the `mobile` project; the desktop project adds nothing at a forced 375px viewport.
4. One test per route; after `goto` (status 200), wait for `load`, read `document.documentElement.scrollWidth/clientWidth`, and assert `scrollWidth <= clientWidth` with the route in the message.
5. If any route overflows, fix the offending styles in its module.

## Tests first

- `e2e/overflow.spec.ts`: one test per route. Proves no horizontal scroll at 375px. Sanity-check that it can fail by temporarily injecting a wide element (not committed).

## Risks and open questions

- Behaviour may already be correct, in which case the test passes first time; noted in progress.
