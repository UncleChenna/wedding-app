# TICKET-175: invitation photo upload pipeline

## Scope and acceptance

Implement an admin-only upload boundary separate from the future design editor.
Validate actual decoded image content against MIME, byte and pixel limits. Reject
invalid and ambiguous containers, strip metadata, apply EXIF orientation and emit
a canonical approved format with dimensions and a small blur placeholder. Return
an application-owned asset reference, never accept an arbitrary remote URL.

Base: develop c9c9e66010ee773189477139d4f8b0d30cf481e1. Prerequisite TICKET-088 is
done in the live ledger. No UI redesign or editor integration belongs here.

## Implementation sequence

1. Define input/output limits and tests for empty, oversized, MIME-mismatched,
   malformed, animated and trailing-payload files; authorization precedes decoding.
2. Use a maintained image decoder, not header-only checks. Proposed direct runtime
   dependency: sharp0.35.5, already present transitively through installed Next.
   Obtain the required native-dependency/lockfile approval before adding it.
3. Decode with a pixel ceiling, auto-orient, strip metadata and re-encode as WebP.
   Generate the blur placeholder from canonical pixels; avoid preserving original
   filenames, EXIF or input bytes. Test orientation and decoder failures.
4. Prepare a concrete persistence/access/retention design consistent with the
   repository's Drizzle-only data rule; request any required schema/policy approval
   before applying it. No production account or service is introduced implicitly.
5. Add authenticated integration tests with exact synthetic cleanup. Run quick/full
   verification and publish a detailed draft PR while prerequisites remain open.

## Proposed bounds

JPEG, PNG and WebP input only; one static frame; maximum8MiB input,24 megapixels,
and8192 pixels on either axis. Output WebP at most2560 pixels on the longer axis,
without upscaling, at most4MiB; blur image at most24 pixels and8KiB encoded bytes.
Failures are safe return values. Do not claim all conceivable polyglots can be
recognized: strict container checks plus canonical re-encoding are both required.

## Verification and risks

Use real decoder fixtures for MIME mismatch, corrupted/truncated streams, extra
trailing payloads, orientation, metadata stripping and decode/output bounds.
Check unauthenticated and non-AAL2 callers never reach decoding or storage. Test
asset-reference validation, write failures and orphan cleanup. Storage retention
and guest image delivery must be documented before review. Preserve originals only
in disposable test fixtures, never in persistent upload storage.
