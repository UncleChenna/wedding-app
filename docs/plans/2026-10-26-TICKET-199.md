# TICKET-199 — RSVP preview

Build an in-memory RSVP flow for Uchenna and Adaora, 19 December 2026. Attendance → party/meal details → review → yes/no confirmation. Two companions and meal options are explicitly sample rules; no backend, storage or actual RSVP delivery. Theme switching preserves the draft. Clear navigation from /dev and invitation preview.

## Design

Reuse theme tokens: ivory background #FBF8F3, chocolate text #241F1A, primary gold #7A5C24, muted text #665A50, light surface #FFFFFF. Each ordinary section uses background/text/gold; error feedback uses existing semantic tokens. Cormorant display and Inter body in the default theme; alternate theme retains its own fonts. Keep all form text at least 16px and controls 44px.

Mobile: preview bar → couple/date → current-step heading → form → actions. Desktop: quiet couple/date column beside a single generous form column. The signature is the warm, personal confirmation copy, not a dashboard or decorative stepper. A compact step label represents actual progression. No new animations or image requirements.

## Implementation and verification

Pure validation handles trimmed names (1–80 characters), known sample meals and at most two companions. Use existing Input, Select, RadioGroup and Button components; focus each new step and invalid control. Stable companion ids preserve input identity. Test empty/invalid input, add/remove limits, back navigation, theme switching, both outcomes and reset. Browser tests assert no mutation requests, axe, 44px targets, reduced motion and screenshots of all states at 375/768/1280 in both themes. Run quick/full gates, push a detailed PR and merge only with green CI under the approved preview exception. TICKET-201 retains performance/device release QA; TICKET-015 remains paused.
