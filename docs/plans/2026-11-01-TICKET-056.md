# 2026-11-01 · TICKET-056 · Sign gate pass tokens with Ed25519

**Outcome.** The server signs a compact gate pass for an invitation. Anyone holding a public key can verify it
without the server. Key handling and rotation are documented.

**Contract.** [ADR 0020](../decisions/0020-gate-pass-credential.md) sets the payload: `v`, `kid`, `inv`, `ver`,
`iat`. The ticket text also lists party size, but the approved ADR keeps the allowance out of the pass and reads it
from the scanner's guest list, so the ADR wins.

## Steps

1. **Encoding and verification:** `src/modules/checkin/lib/gate-token.ts`, isomorphic (no `node:` imports) so the
   scanner can reuse it in TICKET-057.
   - Zod payload schema.
   - Canonical base64url encoding.
   - A `payload.signature` token, length-capped at 512.
   - `verifyGatePass` using WebCrypto Ed25519 against a key ring.
   - Expected failures are return values: malformed, unknown key, bad signature, issued in the future (more than
     600 s by default, ADR row 11).
2. **Signing:** `src/modules/checkin/server/signing.ts` (`server-only`).
   - Load `GATE_SIGNING_KEY_ID`, `GATE_SIGNING_PRIVATE_KEY` (base64url PKCS#8 DER) and the optional
     `GATE_RETIRED_PUBLIC_KEYS`, validated with Zod.
   - Sign with `node:crypto`.
   - Export the public key ring.
3. **Public key endpoint:** `GET /gate/keys`, returning the current and retired public keys with no personal data.
   It returns 503 with a generic message when keys aren't configured.
4. **Key generation:** `scripts/gate-keygen.ts` (`pnpm gate:keygen`) prints a new key pair as env lines.
5. **Docs:** ADR 0021 (key handling and rotation), `.env.example` entries, module README.

## Tests

- **Round trip:** sign, then verify.
- **Fuzz:** 1,000 tampered cases, mixing string-character and decoded-byte flips in both segments. All must fail.
- **Rejected input:**
  - non-canonical base64url
  - oversized or malformed tokens
  - an unknown `kid`
  - issued more than 600 s in the future
- **Rotation:** a retired key still verifies old passes, and removing it stops them.
- **Key loading:** missing or invalid env is an error result.
- **Server-only guard:** `signing.ts` imports `server-only`; no `"use client"` file and nothing in
  `checkin/lib` imports server signing or reads the private key variable.
- **Endpoint:** the route handler returns only public keys and the expected cache headers.
- **Gate:** `pnpm verify`.
