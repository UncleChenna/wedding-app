# TICKET-181 implementation plan

Base develop c9c9e66010ee773189477139d4f8b0d30cf481e1. Owner divine.

Implement server-side theme draft persistence and atomic activation, separate from
TICKET-098 editor controls. Preserve light/dark pairing and existing presets.

1. Establish AAL2 authorization at public admin action boundaries before validation
   or database access. Keep theming services internal and dependency-testable.
2. Reuse loadTheme for canonical schema, curated fonts, AA named-pair failures,
   QR polarity and fixed status meanings. Return expected validation failures.
3. Separate editable drafts from published snapshots. Saving an active theme's
   draft must never modify the live theme. Inspect existing themes/event_settings
   before choosing storage; any generated migration gets exact-path review first.
4. Serialize activation, validate both schemes, publish a complete snapshot and
   update the singleton selection atomically. Invalidate tagged caches after commit.
   Interpret single-active invariant per light/dark slot, preserving current support.
5. Read custom published themes on the server before hydration; retain safe preset
   fallback for unavailable/invalid stored configuration. Check artifact consumers.
6. Unit tests first; isolated PostgreSQL tests for authorization, invalid drafts,
   repeated saves and concurrent activation. Browser initial HTML/artifact checks,
   all-theme UI regression review, quick/full verification and detailed draft PR.

Risks: editing live tokens accidentally, cross-scheme mismatch, preset-ID collision,
partial activation, stale cache/artifact results, unavailable local database, and
migration numbering shared with other pending PRs. No RLS policy changes, production
migration, dependency changes or editor UI in scope. Do not claim device checks.
