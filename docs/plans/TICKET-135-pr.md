# Ticket

Ticket: TICKET-135

# Summary

The PRD asks for visual regression screenshots of every guest page, in every preset theme, at iPhone SE, iPhone 15,
mid-range Android, iPad and desktop sizes. This adds that suite and its CI job.

- **Coverage:** 140 committed baselines, from 7 guest routes × 4 themes × 5 device sizes.
- **Detection:** any visual change, down to a one-step colour change in a theme token, fails CI.

# Changes

- **`e2e/regression/guest-pages.spec.ts`** (new):
  - **Pages:** `/`, `/invite`, `/lost-link`, `/order`, `/offline`, an invitation (`/i/<fixed token>`) and its gate
    pass (`/p/<pass>`).
  - **Themes and sizes:** every theme, applied the same way as the existing screenshot suite. Five PRD sizes at 1x
    density.
  - **Screenshot settings:** full-page, with animations off and the caret hidden.
  - **Masking:** the signed QR code is masked, since it changes every run by design.
  - **Fixture:** the invitation, guest and RSVP are fixed and idempotent, so parallel workers share one set.
- **Baselines:** `e2e/regression/guest-pages.spec.ts-snapshots/*-regression-linux.png`, 140 files, about 8 MB.
  They're generated by CI's own Linux runner; local renders (`*-darwin.png`) are git-ignored.
- **`playwright.config.ts`:** a `regression` project at 1x density. The `mobile` and `desktop` projects ignore it.
- **`scripts/test-visual-regression.ts`** (new):
  - **Setup:** throwaway gate signing keys (so the pass page renders) and a staff secret.
  - **Missing baselines:** it runs with `--update-snapshots=missing`, then fails and lists any baseline it had to
    create.
- **`.github/workflows/ci.yml`:** a new job, "visual regression (guest pages)". It migrates, builds, and runs the
  script. On failure it uploads the `visual-baselines` artifact (new or diff images) for review.
  - This is a CI change: one new job, nothing else altered.

# Acceptance criteria and evidence

- [x] **A 1px colour change in a token fails the visual suite (proved).**
  - Changing ivory-gold's `background` from `#FBF8F3` to `#FBF8F4` (one unit in one channel) failed all 30
    ivory-gold screenshots. Reverted, they all passed.
  - With Playwright's default colour tolerance (0.2), that change was missed, so the suite uses `threshold: 0`.
    `maxDiffPixelRatio: 0.002` absorbs anti-aliasing noise.
  - The proof ran locally against local baselines. The same settings apply on CI.
- [x] **Baselines committed for every guest route × theme × device.**
  - 140 Linux baselines from CI run 43206580221 are committed. The next CI run compares against them and passes.

# Verification

- **Local stability:** a baseline run, then a comparison run, both 140 out of 140, twice. That came after fixing a
  fixture race where two workers both added the guest.
- **CI:** first run 120 passed with 20 skipped; the pass link was missed because it's absolute. After the fix, run
  43206580221 generated all 140; runs 43215328532 and 43219789885 compared against them and passed (140 of 140).

# Not tested and limitations

- **Admin and staff pages** are out of scope by the ticket.
- **Rendering engine:** the suite renders in Chromium only, at device sizes. It doesn't use real iOS/WebKit
  rendering; that's for the real-device test session (TICKET-114).
- **Intentional design changes** fail this job until new baselines are committed from its artifact.

# Risks and rollout

- **Repo size:** about 8 MB of images now, and more each time baselines are refreshed.
- **CI time:** about 3 minutes for the new job, which runs alongside the others.
- **Rollback:** revert the PR.
