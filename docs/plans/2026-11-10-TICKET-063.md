# TICKET-063 implementation plan

Build authenticated manual guest search inside the existing `/checkin` scanner
and its standalone offline shell. Keep one durable private cache authority, not
another cached route or public guest directory.

1. Pure bounded search normalizes case/accents and token order, permits one typo
   in longer name tokens, searches primary/tag-along names, and returns distinct
   household selections. Require two characters; cap results and disclose more.
2. Online POST search/read endpoints authorize the live gate staff/device before
   reading names. Same-origin, strict bounded input and no-store output; never
   put names in URLs or logs. Reauthorize after reads. Selecting a household
   rereads current status/count/table and records a zero-person manual observation
   through TICKET-062's server contract, retaining its five verdicts.
3. Reuse the existing admission count/uncertain-retry/receipt UI and locked atomic
   admission transaction with an explicit manual selection (invitation/version).
   The endpoint derives manual input metadata server-side; no forged QR or signing
   key is required. Preserve exact request IDs and prevent switching guests while
   admission outcome is uncertain.
4. TICKET-065 worker supplies transient authorized rows for offline search. Session
   invalidation/expiry clears names and results. Cached selections stay read-only;
   reconnect requires a fresh selection/read before admission. TICKET-066 retains
   offline mutation/outbox/sync, not claimed here.
5. Camera-denied recovery opens this search directly; ≥18px controls/results,
   keyboard focus, 44px targets, all-theme screenshots and actual PIN-authenticated
   browser flow. No extra private HTML caching or persistent window storage.

Verification: red normalization/typo/duplicate and auth/input/lifecycle regressions,
SQL manual observation+admission/counter/replay proof, actual denied-camera→search
primary/tag-along→partial admission and offline cache/read tests; all themes at
375/768/1280, axe, keyboard/reduced motion, quick/full CI. Physical devices remain
release-gated, not certified by emulation. PR stays draft until 062/065 merge.
