# Plan: Verify database bootstrap is idempotent

- Task: TICKET-003
- Module(s): shared (database scripts)
- Date: 2026-10-22

## Goal

Prove migrations and seed are repeatable on a fresh local stack, and add a committed check that fails when any public table lacks row-level security.

## Acceptance criteria

- [x] `pnpm db:migrate` twice in a row succeeds; the second run applies nothing.
- [x] `pnpm db:seed` twice yields identical row counts.
- [x] A committed check (`pnpm db:check-rls` or a test) fails if any public table lacks RLS.
- [x] Evidence (commands and counts) is recorded in the ticket notes.

## Approach

1. `scripts/db-check-lib.ts`: pure `tablesMissingRls()` (empty schema is an error) and `formatCounts()` (sorted, diffable).
2. `scripts/db-check.ts`: `rls` queries `pg_class.relrowsecurity` for public tables; `counts` prints per-table counts and `drizzle.__drizzle_migrations` count.
3. `package.json`: `db:check-rls`, `db:counts`.
4. Run the evidence on the worktree stack; fix anything non-idempotent (nothing was).
5. Document in AGENTS.md, the db-migration skill and docs/current-state.md.

## Tests first

`scripts/__tests__/db-check.test.ts`: all-protected passes; unprotected tables are named and sorted; empty schema throws; counts format is stable. Failed before the module existed.

## Risks and open questions

- CI does not run `db:check-rls` yet; adding it is a CI change for the reviewer to approve.
