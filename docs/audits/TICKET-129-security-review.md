# TICKET-129 security review

Reviewed 13 November 2026 against develop `6b2c9d3ec67fcf2ae83250cf3b34c84c0da9ac42`, including merged staff ordering and reviewed admission recovery. This is a source-level application review with focused negative tests, not an external penetration test or production configuration certification.

## Result and findings

No unresolved high/critical application finding was identified in the reviewed scope. Two moderate findings were reproduced and fixed in this ticket. Release remains conditional on the existing operational/device gates; this report does not certify physical devices, production secrets, edge limits or provider configuration.

| Finding                                                | Risk and reproduction                                                                                                                                                                                                                                                              | Fix and retest                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-129-01: station mutation missing Origin validation | A signed-in station request with missing or hostile same-site Origin and `text/plain` JSON was accepted with 200. `SameSite=Strict` limits cross-site cookies but does not separate sibling origins; a hostile same-site origin with a known ticket ID could attempt a mutation.   | Exact Origin required before reading the body or calling the move service. Regression now returns 403 and proves no write. Existing same-origin outcomes remain tested.                                                                                                                                                                      |
| SEC-129-02: JSON body limits applied after buffering   | Guest order, gate admission/read/sync buffered the entire request before checking bytes; station moves had no transport bound. Oversized chunked bodies exhausted resources before schema rejection. All five regressions showed the remainder was consumed rather than cancelled. | Shared bounded stream reader stops/cancels at the byte limit and releases its reader. Limits: 8 KB order/admission/read,4 KB station move,128 KB sync. Forged Content-Length cannot bypass actual byte counting. Existing malformed/oversized response codes and valid business outcomes retained. Six initial failing regressions now pass. |

These are bounded fixes within TICKET-129, not deferred high/critical findings. The gate is: any later high/critical finding must remain linked to this audit/release blockers until a bounded fix and successful retest are recorded; merely creating a follow-up ticket is insufficient for release.

## Coverage and method

Read every exported Server Action and API route adapter, then its authorization/data boundary; checked capability vs database-ID handling, role isolation, input bounds, mutation origins, privacy headers/projections, log redaction and replay behavior. Reviewed installed Next.js16.4.2 `node_modules/next/dist/docs/01-app/02-guides/data-security.md`: actions are reachable POST boundaries, so layout/proxy checks alone are not accepted as authorization. Server Action origin/body handling remains the framework's protection; custom route handlers need their own checks.

Inventory: **38 exported actions in 21 files; 35 route handlers.** The tables enumerate every discovered entry point at this baseline.

## Cross-cutting conclusions

- **Capabilities and IDOR:** new invitation links use 256 random bits (legacy 128-bit tokens remain accepted); the editable capability is resolved server-side and never replaced by a submitted invitation UUID. Party mutations constrain guest IDs to the locked invitation. Read-only Ed25519 QR tokens carry invitation/version identity, never the editable token; issuance rechecks RSVP eligibility/version and revoked/reissued state. Forwarded valid passes remain bearer credentials by PRD design, bounded by per-seat admission and reconciliation rather than an identity claim.
- **Admin and staff:** all privileged actions invoke live admin ready/AAL2 guards or a guarded delegated service. OTP/MFA bootstrap is intentionally AAL1 with allowlist/factor ownership checks. Admin content readers/components enforce page access in addition to layout/proxy. Signed staff session/device cookies are HttpOnly, Secure in production and `SameSite=Strict`; live role, version, device revocation and expiry checks remain mandatory. No client-supplied actor replaces server identity.
- **Data and injection:** Drizzle parameterized operations, strict boundary schemas, React escaping, theme CSS closing-tag rejection, fixed export filenames and spreadsheet formula escaping were inspected. Photo uploads authenticate first, reject remote URLs/SVG, cap streamed bytes and decode/normalize bounded pixels before storing stripped WebP. No new raw SQL or HTML sink is added.
- **Offline/recovery:** private snapshots bind session/actor/expiry; retained unacknowledged evidence is not discarded on logout or storage warnings. Recovery imports require current admin review and append-only transactional evidence; signed device receipts prove exact committed records only. Offline revocation necessarily needs refresh and remains a runbook/device gate.
- **Headers and secrets:** private response paths use no-store and restrictive referrer/robots headers; public health/keys/menu/worker endpoints expose intentionally public projections. Application logs use fixed messages/classifications rather than tokens, raw requests, PINs or database exceptions. Browser environment allowlisting/server-only boundaries remain in place. The existing CSP intentionally permits inline scripts/styles (ADR 0006); that defense-in-depth limitation is documented, not claimed as a nonce policy.
- **Deployment boundary:** production Auth rate limits, trusted Vercel forwarding configuration, RLS/provider policies, key provisioning/rotation, HTTPS and browser storage/device behavior still require their existing release checks. No real secrets, guest database, external attack traffic or production reset was used in this review.
