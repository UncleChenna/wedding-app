# Deployment configuration

This document describes configuration shape, not a deployed environment. TICKET-147 still owns provider/preview setup; TICKET-148 still owns assigning separate environment values, rotation prerequisites and verifying startup in the actual deployment. No service, secret or deployment is created by the preflight.

## Explicit release check

Run `pnpm env:release --profile preview` or `pnpm env:release --profile production` with the intended environment already injected by the provider or a private local process. The command does not load `.env.local`, print values, contact services or mutate configuration. Both profiles check the complete currently implemented wedding experience: admin access, staff sessions, gate signing, station Realtime and scheduled order alerts. An intentionally incomplete development preview can still use the ordinary build, but cannot claim this release preflight passed.

A failure prints variable names and fixed reasons and exits nonzero. Success proves configuration shape only: it does not establish database connectivity, correct project ownership, DNS, email delivery, scheduling, provider permissions, key entropy, secret-store access or separation from another environment. Set the provider's explicit pre-deployment step to this command under TICKET-148; the default local build and existing CI do not acquire new secret requirements.

Use distinct databases, signing keys and symmetric secrets for preview and production. Do not supply production credentials to untrusted PR previews. The command cannot compare two secret stores; record that review under TICKET-148 and rotation under TICKET-125.

## Application variables

The table is tested against `.env.example` and the preflight inventory. `NODE_ENV` is supplied by the runtime rather than copied from the example. Runner flags and provider metadata are not application configuration and are documented separately as comments in `.env.example`.

| Variable                               | Local behavior                                               | Preview and production release requirement                                                                                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NODE_ENV`                             | Defaults to development in the shared parser.                | Must be production for the deployed build, including previews.                                                                                                                                                     |
| `DATABASE_URL`                         | Required; managed local Postgres is supported.               | Remote Postgres URL with credentials and `sslmode=require`, `verify-ca` or `verify-full`; prefer verify-full. No local/private literal host. Connectivity and certificate policy still need deployed verification. |
| `LOG_LEVEL`                            | Optional; defaults to info.                                  | Optional supported level: debug, info, warn or error. Do not log guest secrets.                                                                                                                                    |
| `NEXT_PUBLIC_SITE_URL`                 | Required; loopback HTTP allowed locally.                     | HTTPS origin without credentials, path, query or fragment; use the environment's canonical site.                                                                                                                   |
| `NEXT_PUBLIC_SUPABASE_URL`             | Required; local Supabase allowed.                            | HTTPS origin without credentials, path, query or fragment; use the environment's project.                                                                                                                          |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Required public project key.                                 | Publishable key or legacy anon JWT shape; never a secret key or service-role JWT. Project membership and signature are not established by this offline check.                                                      |
| `ADMIN_EMAIL_ALLOWLIST`                | Empty denies all admin sign-ins.                             | At least one exact valid email; no wildcards. Provider email delivery and MFA still require verification.                                                                                                          |
| `STAFF_SESSION_SECRET`                 | Empty disables staff sign-in.                                | Required independent 32-byte lowercase hex secret. Generate cryptographically; shape checks cannot establish entropy.                                                                                              |
| `SUPABASE_JWT_SECRET`                  | Empty disables station Realtime signing; boards can refetch. | Required project JWT secret, at least 32 characters, distinct from other symmetric secrets. Confirm project signing mode and Realtime authorization in deployment.                                                 |
| `ALERT_DRAIN_SECRET`                   | Empty leaves the alert drain unavailable.                    | Required independent 32-byte lowercase hex secret. Configure the scheduler separately; the preflight does not schedule it.                                                                                         |
| `GATE_SIGNING_KEY_ID`                  | Optional until passes are issued.                            | Required valid current key identifier.                                                                                                                                                                             |
| `GATE_SIGNING_PRIVATE_KEY`             | Optional until passes are issued.                            | Required Ed25519 private key in base64url PKCS8 format, validated by the same loader that signs passes. Generate with `pnpm gate:keygen` and store privately.                                                      |
| `GATE_RETIRED_PUBLIC_KEYS`             | Optional comma-separated retired public keys.                | Optional; if present, all identifiers/SPKI keys must pass the existing gate loader. Keep still-valid old public keys during rotation.                                                                              |

Unknown `NEXT_PUBLIC_*` names are rejected because those values become browser-visible. Server credentials stay in the provider's private environment store. Platform metadata such as `VERCEL`, `VERCEL_ENV` and `VERCEL_GIT_COMMIT_SHA` is supplied by the provider; when `VERCEL_ENV` is supplied, it must match the selected profile.

## Remaining deployed evidence

TICKET-148 must set values in the intended provider scopes, run the explicit check there, demonstrate a missing required variable blocks its configured deployment step, and verify real startup. TICKET-147 must demonstrate the preview URL and toolchain. Separate release tickets retain database migrations/backups, RLS, real phone installation/scanning, performance, mail/provider setup and rollback. Passing this local command does not mark any of those complete.
